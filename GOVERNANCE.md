# Governance

## Scope

This repository is the open project: the `apex-context` CLI (report, gate, install-hook, bench), its docs, examples and tests, under Apache-2.0. Apex Capsule IDE is a separate commercial desktop product and is not part of this project; it has its own code and roadmap. The open project does not depend on it, and decisions here are made on this project's merits.

## Decisions

Maintainers decide. Most changes are decided in pull request review: one maintainer approval and passing CI is enough for ordinary changes. Changes that touch the privacy rules in [CONTRIBUTING.md](CONTRIBUTING.md), the CLI's public flags, the package's license or this governance need approval from two maintainers, or from the only maintainer if there is just one, after the proposal has been open for at least a week. Disagreements are settled by discussion in the issue or pull request; if that does not converge, the maintainers vote and a simple majority decides. The reasoning is written down in the thread.

## Maintainers

The current maintainers are listed in the repository's GitHub settings. To become a maintainer: contribute steadily over several months (code, review, issue triage, tasks or docs), show care for the privacy rules, and be nominated by a maintainer or by yourself in a private report to the maintainers. Existing maintainers approve by consensus. A maintainer who is inactive for a long period may be moved to emeritus status, and can return on request.

## Conduct and security

The [Code of Conduct](CODE_OF_CONDUCT.md) applies everywhere. Security and privacy bugs go through [SECURITY.md](SECURITY.md).
